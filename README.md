# FiberPlan 3D

Frontend-only прототип для проектирования оптоволоконной сети поверх 3D-модели села.
Интерфейс построен на адаптированных принципах IBM Carbon; локальные правила
зафиксированы в [`DESIGN.md`](./DESIGN.md).

## Возможности

- интерактивная оптимизированная 3D-сцена;
- географическая карта с узлами и трассами;
- добавление точки сети кликом по поверхности модели;
- соединение двух узлов выбранным типом кабеля;
- автоматический расчёт длины и технологического запаса;
- анимированное отображение активных и планируемых линий;
- прямой импорт локального GLB или ZIP с `tileset.json` и B3DM-тайлами;
- автоматический выбор облегчённого LOD для больших ZIP;
- определение названия территории по координатам 3D Tiles через OpenStreetMap;
- отображение границ 3D-модели на карте;
- добавление муфт и соединение узлов как в 3D, так и непосредственно на карте;
- навигация по 3D-сцене стрелками и скрываемые боковые панели;
- отдельное отображение подземной магистрали на поверхности и карте;
- сохранение схемы в `localStorage`;
- экспорт плана сети в JSON.

## Запуск в WSL

```bash
cd ~/projects/fiber-village-3d
nvm use
npm install
npm run dev -- --host 0.0.0.0
```

Откройте адрес, который Vite напечатает в терминале (обычно
<http://localhost:5173> или <http://localhost:5174>).

## Работа с реальной моделью

1. Нажмите **Открыть ZIP / GLB**.
2. Выберите подготовленную модель `.glb` или исходный архив вроде `f.zip`.
   В ZIP приложение само найдёт верхний `tileset.json`, связанные JSON и B3DM.
3. Выберите **Новый узел** и укажите точки подключения на поверхности модели.
4. Выберите тип кабеля.
5. Нажмите **Проложить кабель** и последовательно выберите два узла.

На карте действуют те же инструменты: в режиме **Новый узел** кликните в
нужном месте, а в режиме **Проложить кабель** выберите два существующих
маркера. Пунктирная синяя рамка показывает территорию, покрытую 3D-моделью.
Стрелки клавиатуры перемещают камеру по сцене; кнопки панелей в верхней строке
скрывают левую и правую части интерфейса.

Файл модели остаётся на компьютере пользователя. Backend и предварительная
распаковка не требуются. Чтобы не перегружать память, приложение читает архив
по записям и автоматически ограничивает объём выбранного LOD примерно 24 МБ.

Быстро проверить структуру архива без запуска интерфейса:

```bash
npm run check:zip -- /mnt/c/Users/winux/Downloads/f.zip
```
